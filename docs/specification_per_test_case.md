# テストケースごとのカバレッジ取得機能 仕様書

## 1. 概要
本プロジェクトでは、JavaコードカバレッジライブラリであるJaCoCoを拡張し、テストケース単位でのカバレッジ計測を可能にします。
従来のJaCoCoでは、実行セッション全体またはクラス単位での集計が主でしたが、本拡張により「どのテストケースがどのコード行を通過したか」を詳細に把握できるようになります。

## 2. 目的
- **テストの影響分析 (TIA: Test Impact Analysis)**: コード変更時に影響を受けるテストケースのみを特定し、実行時間を短縮する。
- **デバッグの効率化**: 特定のテストケースが期待通りにコードを網羅しているかを確認しやすくする。
- **デッドコードの特定**: どのテストからも実行されていないコードを、テスト単位の視点から詳細に分析する。

## 3. 実装方針と優先順位

### 3.1. 優先順位
本プロジェクトでは、**Javaエージェントによるテスト実行のフックとデータ収集の安定化を最優先事項**（Priority: High）とします。レポート出力機能（Priority: Low）については、まず正しい実行データ（`.exec`）が生成されることを確認した後に段階的に実装します。

### 3.2. エージェントによる自動拡張 (Priority: High)
- **最優先で実装**: テスティングフレームワーク（JUnit等）の実行をフックする仕組みをエージェント内で自動的に導入します。
- 具体的には、Javaエージェントによるクラスのトランスフォーム（バイトコード操作）を利用し、JUnitの各テストクラスに対して `RunListener` (JUnit 4) や `TestExecutionListener` (JUnit 5) を自動的に登録するコードを注入します。
- これにより、ユーザーは既存のテストコードやビルド設定を変更することなく、エージェントを有効にするだけでテストケースごとのカバレッジを取得可能になります。
- テスト開始直前に `IAgent.setSessionId(String)` を呼び出してセッションIDを切り替え、テスト終了時にデータを管理する制御を確実に行います。

### 3.3. JUnitテストの解析とセッションIDの割り当て
- テスト実行直前に、実行対象のJUnitテスト（JUnit 4 または JUnit 5）を解析します。
- テストケース（クラス名 + メソッド名）ごとに一意なセッションIDを生成し、JaCoCoのRuntime API (`IAgent.setSessionId(String)`) を用いて動的に割り当てます。
- これにより、出力される実行データ (`.exec`) 内の各 `SessionInfo` ブロックが、特定のテストケースの開始タイミングを示すマーカーとして機能します。

### 3.4. データ管理の方針 (`org.jacoco.core`)
- 既存の `ExecutionData` および `SessionInfo` のデータ構造をそのまま利用します。
- テストケースごとに `setSessionId` を呼び出すことで、`.exec` ファイル内には「SessionInfo (テストA) -> ExecutionData群 -> SessionInfo (テストB) -> ExecutionData群」という形式でデータが記録されることを保証します。

### 3.5. レポートの拡張 (Priority: Low)
- 実行データ形式 (`.exec`) の変更は行いません。
- 当面は標準のレポートツールでの読み込みが可能であることを最低条件とし、将来的にテストケースごとのフィルタリングや集計機能を `org.jacoco.report` に追加します。
- 実現に際しては、同一クラスに対する複数の `ExecutionData` をセッションIDに基づいて分離するロジックを段階的に導入します。

## 4. 利用方法（想定）
1. JaCoCoエージェントに新しいオプション（例: `pertest=true`）を指定して実行します。
2. テスティングフレームワーク側で、テストの開始/終了時にJaCoCoのRuntime APIを呼び出します。
3. 生成された `.exec` ファイルをレポートツールで解析します。

## 5. 今後の課題
- 大規模なプロジェクトにおけるメモリ使用量の増大への対策。
- 並列実行されるテストケースの正確なトラッキング。
- 主要なビルドツール（Maven, Gradle）との連携。
