# JaCoCo データ構造仕様書

本ドキュメントでは、JaCoCoがコードカバレッジ情報を管理・保存するために使用するデータ構造と、実行データ（`.exec`）のバイナリフォーマットについて説明します。

## 1. 主要なクラス構成

JaCoCoのコアロジック（`org.jacoco.core`）における主要なデータ保持クラスは以下の通りです。

### 1.1 ExecutionData
単一のJavaクラスに対する実行データを保持します。
- `id`: クラスの識別子（クラスファイルのCRC64チェックサム）。
- `name`: クラスのVM名（例: `org/jacoco/core/data/ExecutionData`）。
- `probes`: `boolean[]` 配列。各要素がクラス内の特定のプローブ（実行ポイント）に対応し、実行された場合は `true` となります。

### 1.2 ExecutionDataStore
複数の `ExecutionData` オブジェクトをメモリ上で管理するコンテナです。内部的には `id` をキーとした `Map<Long, ExecutionData>` を保持しています。

### 1.3 SessionInfo
計測セッションに関するメタデータを保持します。
- `id`: セッションの識別子。レポート出力時にどのテストか判断できるようなID（例: `ClassName#methodName`）を振ることを仕様とします。
- `startTimeStamp`: セッション開始時刻（エポックからのミリ秒）。
- `dumpTimeStamp`: データがダンプされた時刻（エポックからのミリ秒）。

---

## 2. 実行データ形式 (.exec) バイナリフォーマット

`.exec` ファイルは、複数のデータブロックで構成されるバイナリストリームです。

### 2.1 共通データ表現
JaCoCoはストレージ効率を高めるために、独自の `CompactDataOutput` / `CompactDataInput` を使用しています。

- **VarInt (可変長整数)**: 小さな正の整数を1〜5バイトで表現します。
  - 各バイトの最上位ビット（0x80）が「次のバイトがあるか」を示します。
  - 下位7ビットが実際の値を保持します。
- **Boolean Array (ビットパック)**: `boolean[]` を1ビットずつパックしてバイト配列として書き込みます。
  - 最初に `VarInt` で配列の長さを書き込みます。
  - 続いて、各ブール値を下位ビットから順に埋めたバイトデータを書き込みます。

### 2.2 ブロック構造
各ブロックは1バイトの「ブロック識別子」から始まります。

#### Header Block (0x01)
ファイルの先頭に必ず1つ存在します。
- `0x01` (byte): ブロックタイプ
- `0xC0C0` (char): マジックナンバー
- `0x1007` (char): フォーマットバージョン

#### SessionInfo Block (0x10)
セッション情報を記録します。
- `0x10` (byte): ブロックタイプ
- `id` (String): セッションID（UTF-8形式）
- `startTime` (long): 開始タイムスタンプ
- `dumpTime` (long): ダンプタイムスタンプ

#### ExecutionData Block (0x11)
特定のクラスの実行データを記録します。
- `0x11` (byte): ブロックタイプ
- `id` (long): クラスID
- `name` (String): クラス名（UTF-8形式）
- `probes` (boolean array): プローブデータ（ビットパック形式）

## 3. テストケースごとのカバレッジ識別の方針

今回の拡張では、実行データ形式（`.exec`）のバイナリフォーマットを変更せず、既存の仕組みを工夫してテストケースごとのカバレッジを識別します。

### 3.1 SessionInfo によるセッション境界の活用
- テストケース（例: `TestClass#testMethod`）の開始直前に、JaCoCo Runtime API を通じて `sessionId` をそのテストケース名に設定します。
- テスト終了時（または適切なタイミング）でデータをダンプすることで、`.exec` ファイル内には以下のような順序でデータが記録されます：
    1. `SessionInfo` (id = "TestA")
    2. `ExecutionData` 群 (TestA 実行中にヒットしたクラス分)
    3. `SessionInfo` (id = "TestB")
    4. `ExecutionData` 群 (TestB 実行中にヒットしたクラス分)

### 3.3 レポート生成への活用
- レポート生成ツール（`org.jacoco.report`）側で、`.exec` ファイルをストリームとして読み込み、`SessionInfo` ブロックをセッションの切り替わりとして認識します。
- 次の `SessionInfo` が現れるまでに読み込まれた `ExecutionData` は、その直前の `SessionInfo` に属するものとして管理します。
- **JSON形式でのデータ出力**: レポート生成ツールは、解析結果をSPAで利用可能なJSON形式で出力することに注力します。SPA本体は、プロジェクトに同梱されたテンプレート実装を使用し、このJSONを読み込むことで動的なレポートを表示します。
- これにより、同一のクラスであっても「どのテストケース（セッション）で実行されたか」を個別に保持し、特定のテストケースのみのカバレッジレポートを生成したり、SPA形式のHTMLレポート上で双方向のトレーサビリティ（行→テスト、テスト→コード）を実現することが可能になります。
